C. ROCKET CAMPAIGN ROUTING
Campaign contacts must be partitioned and assigned across configured routes.

Each route contains:
- WABA
- Phone Number
- Template
- Priority
- Configured TPS
- Current TPS
- Queue depth
- Route status

TPS must be configurable independently for each phone number. The platform must not impose an artificial low TPS limit; actual throughput must still respect provider/Meta limits.

D. UNIVERSAL MULTI-TEMPLATE SYSTEM — CRITICAL
Support selecting multiple templates in one Rocket Campaign.

Automatically read the metadata/components of every selected template. Do not hardcode any fixed number of variables.

HEADER:
- Detect no header, text header, image header, video header and document header
- If compatible selected templates support IMAGE header, show a single image upload option
- Allow the uploaded image to be applied to all compatible selected templates
- Do not apply it to incompatible templates
- Show clear compatibility status

BODY VARIABLES:
- Detect all body variables dynamically regardless of how many exist
- Allow mapping from CSV columns
- Allow static values
- Allow one common mapping to be reused across compatible selected templates
- Example: CSV column "name" can map to {{1}} across compatible templates

BUTTON VARIABLES:
- Detect dynamic button/URL parameters
- Support CSV column mapping and static values
- Support different button variable structures across templates

If templates have incompatible variable structures, clearly show which template needs additional mapping. Never silently send with missing variables.

Store the complete mapping configuration persistently in the database.
